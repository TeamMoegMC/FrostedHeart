# 货运站逐步执行任务清单

> 依据：`docs/transport_station_design.md`
>
> 范围：只实现城镇建筑和城镇 `TRANSPORT_CAPACITY` 生产，不包含 KHJ 物流。

## 1. 标注说明

### 复杂度

| 标记 | 含义 |
|---|---|
| `S` | 单点、低耦合改动，验证路径短 |
| `M` | 涉及数个明确接线点，需要定向测试 |
| `L` | 跨模块行为，需要较完整的实现和回归验证 |
| `XL` | 影响持久化、结算和多个界面，错误代价高 |

### 模型选择

模型定位依据 [OpenAI 官方模型文档](https://developers.openai.com/api/docs/models)：

- `GPT-5.6 Sol`：复杂推理、跨模块编码和高风险一致性工作。
- `GPT-5.6 Terra`：能力与成本平衡，适合边界明确的常规实现。
- `GPT-5.6 Luna`：成本敏感、机械性或批量工作。
- `手动`：美术、玩法取舍或必须在游戏内凭体验判断的工作。

推理强度是本项目任务建议，不是模型能力限制。

## 4. 里程碑 B：城镇运力生产

### H03：手动确定城镇运力生产数值

这是玩法决策，交给你手动确定；模型可以在你给出目标后做模拟和校准。

需要明确：

- 哪些居民属性参与生产力，以及各自权重；
- 熟练度上限、满熟练度加成和每日成长速度；
- 每标准工人日生产多少 `TRANSPORT_CAPACITY`；
- 无工人时是否有被动产出；
- 运力是否可无限跨日囤积，若不可，采用上限、衰减还是其他规则。

完成标准：形成一组无歧义、带单位的初始参数和至少两个期望算例。

### T09：实现纯运力日结模型与生产配置

- 新增 Forge 无关的 `TransportStationDailyModel`。
- 实现居民生产力、总生产力、产出量和囤积规则的纯函数。
- 将所有默认值放入 `TownModelParameters.Defaults`，运行时配置引用同一来源。
- 对 NaN、无穷、负值和上限边界做安全处理。
- 先写纯逻辑测试，再接入 Building。

完成标准：给定相同输入得到确定结果；边界输入不产生负资源或非有限值。

### T10：接入生产、熟练度、日报与存档

- 在 `TransportStationBuilding#work` 收集当日名册并调用纯模型。
- 通过 `VirtualResourceAttributeAction` 添加 `TRANSPORT_CAPACITY`，禁止 unsafe 直写。
- 只给实际具有工作机会的居民增加运输熟练度。
- 新增 daily report、forecast 所需状态和带默认值的 Codec 字段。
- 为所有新状态增加净变化守卫，保证旧的里程碑 A 存档可加载。
- 明确无工人、结构失效和参数为零时的停产原因。

完成标准：日结只执行一次、资源只增加一次；存档升级不丢建筑、名册或已有城镇资源。

### T11：实现生产预测与生产页

完成标准：预测与同输入下的实际结算一致；没有日报时显示明确空状态。

## 5. 推荐执行方式

1. 先连续执行 `T00` 至 `T04`，同时由你完成 `H01`。
2. 完成 `T05` 至 `T08` 后暂停代码工作，由你执行 `H02`；基础生命周期未通过前不进入生产阶段。
3. `H03` 可以与里程碑 A 并行讨论，但必须在 `T09` 前冻结第一版参数。
4. 连续执行 `T09` 至 `T13`，再由你执行 `H04`。
5. 根据 H04 反馈只调整配置/纯模型并重复 `T13`、`H04`，通过后执行 `T14`。

若以后增加合成配方、任务线、KubeJS 或整合包配置，应另开任务；届时必须先读取 companion 仓库的
`AGENTS.md`，并分别验证两个 Git 仓库。
