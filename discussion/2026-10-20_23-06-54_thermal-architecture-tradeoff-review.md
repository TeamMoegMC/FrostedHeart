## 比较口径

比较的是保留多核、粗档持续服务与精细恢复的最新方案。单worker、固定细网格、删除自动降级/恢复的建议已撤回，不列入可实施方案。

原设计不等于当前有缺陷的实现。原工程计划§9–16、§24以及后续修订已经要求：并行计算/单处提交、同一区域一个数值执行者、局部变更候选、粗档服务、恢复退避、预付服务空间、保存Accepted与未消费J。这些均是应保留的原设计优点，不冒充新发明，也不能把当前停滞当成原设计承诺的正常行为。

本次有实质差异的部分集中在源接管与Page批次解耦、合并已接管热量的保管责任、精度切换控制权收敛，以及粗档输入的缓存/增量聚合。其余多为兑现原合同。没有新实现测量，以下不提供提速百分比、Bug减少比例或内存净降幅。

## 一、原有优点的保留情况

| 原设计优点 | 修正后方案 | 明确边界 |
|---|---|---|
| 共享工作池利用多核 | 保留同维度独立区域并行；有收益的任务内部并行也可保留，由所属任务归并 | 不改成单worker或仅不同维度并行；仍遵守总预算和相关数据依赖 |
| 大基地不拖住远处小房间 | 保留局部任务、局部提交和服务份额 | 真正热相连的区域仍有物理依赖，不能按坐标远近伪造独立性 |
| 正常区域精细温场 | 保留当前细网格、材料热律、double与数值停止条件 | 不承诺浮点逐位相同，但不能凭重构主动降低正常精度 |
| 正常输入的时间顺序 | 基础重构保留事件顺序和原20tick数值推进 | 不继承已撤回方案中对全部普通事件强制一秒平均的建议 |
| 自动降级及最低服务 | 保留FINE→粗档和粗档持续计算；保留快速降级所需的有界摘要/工作空间 | 粗档必须降低实际求解成本，不能仍周期展开整个细场 |
| 负载解除后恢复精细 | 保留静态准备与粗场推进并存，最终从最新Accepted完成交接 | 当前小摘要不会恢复已经丢失的细节；恢复连续性仍需验证 |
| 热量一次消费、身份不串 | 保留生产/接管/消费账目、源及材料身份、世界效果ACK | 散热和真实移除有明确账目；不能把旧材料的J转给新物体 |
| 保存/卸载/重载一致 | 保留checkpoint封存状态与未消费输入、实际卸载一次导出/取消 | 不恢复“全维度追到当前时间才能保存”的屏障；当前格式重载仍要单独验证 |
| 查询、HUD/IR读取已提交场 | 保留独立区域发布与真实sampleTick | 基础重构不放宽正常40tick门槛，也不把几何失效读数冒充current |
| 全服内存与CPU预算 | 保留原128MiB计费root和共享服务份额 | root不是整个JVM堆；160最低模型节点也不是整个热系统恒定内存/CPU |
| 算子缓存、数组复用、局部更新 | 保留能够明确所有权和并存峰值的优化 | 不为通用接口退回逐元素装箱、全局扫描或整场复制 |

这些能力没有被当成此次简化的代价。既有粗档的精度损失与恢复等待仍然存在，但不重复记成新方案新增的损失。

## 二、基础重构的实质差异与收益

| 改动 | 原设计/当前实现的差别 | 预期收益 | 需要付出的代价或验证 |
|---|---|---|---|
| 源接管脱离Page active/pending整体退休条件 | 原设计要求独立接管；当前IntakeCursor仍把同Page源窗口、绑定及控制进度耦合 | 源A的未来后缀不再阻挡源B的到期前缀；减少结构反向阻塞接管的路径 | 每源/端口的所有权与水位要清楚；接管更顺畅后，未消费积压仍需原预算内有界存储 |
| 已接管热量一个保管所有者 | 原设计明确区分未知目标与已分配份额；实现有SpatialHeatInbox/SpatialHeatStore分别维护记录和摘要 | 减少记录在相邻阶段间迁移、重新计量和时间资格不一致；取消/保存读取同一份权威 | 需保留不同阶段的身份、份额和索引；单一权威不等于单一全局扫描队列，数据布局不好可能变慢 |
| 精度意图与任务执行分工 | 原设计已要求策略发请求；实现中minimumRequested/qualityPending/recoveryPreparing及observeSlice等分散控制 | 减少互相覆盖的降级、恢复和取消状态；一个位置回答当前变更目标及等待原因 | 不能把必要的准备、投影、helper退出和reader释放状态藏掉；执行时机可能在下一个合法片段边界 |
| 两档模型共用领取/取消/提交合同 | 原设计已有同一任务方向，当前仍有多处质量专用出口 | 相同的源前缀不因粗细模式走不同确认规则；同类修复覆盖两档 | 只统一外层生命周期，保留各模型数据布局与内循环，避免统一成低效万能求解器 |
| 并行子工作明确归属一个任务 | 原设计已有账户及完成队列；实现仍需核对全部helper和清理路径 | 一个取消决定、一个结果归并点、一个费用归属；降低迟到结果与资源交接错误机会 | 实际运行helper仍须退出，不能通过早退费简化；不新增相互等待的子线程树 |
| 稳定粗档布局的输入缓存/聚合 | 粗数值节点虽有界，接管、归属处理、材料和保存未必有界常数成本 | 减少求解端同节点重复映射和布局重建，把稳态与变化成本分开 | 缓存占内存且有失效责任，施工频繁时收益可能有限；主线程真实源变化仍需处理 |
| 等待依据由其任务所有者提供 | 原设计要求WAITING携带依赖，实际hasWork/ready仍分布多层 | 故障时能定位具体输入/结构/容量/reader/helper及解除事件，减少靠遍历日志猜测 | 保留必要索引和诊断；应复用执行状态，不能另建需要同步的“诊断状态机” |

以上为可实施的结构收益或预期收益；“永久等待已经消失”“正常CPU下降”“内存下降”都必须由后续源码和真实运行证明。减少任务状态的自由组合也不意味着温度模型、拓扑分片、相变和异步读者本身不再复杂。

## 三、真正可能损失的优点：默认不捆绑，单独评审

基础重构不要求以下策略变更。原设计已有相应保护，只有进一步调整其时机/阈值才构成额外收益和额外损失。

| 可选取舍 | 相比原策略可能失去的优点 | 可以换取的收益 | 建议与约束 |
|---|---|---|---|
| 以可信规模上界更早直接选择粗档 | 部分本可完成精细构建的区域较早失去局部细节，可能少一次精细计算机会 | 避免明显过重区域先付一轮大fine构建/取消成本 | 仅对已明确超额的场景评估，不能仅按篝火个数把正常房间误降级；正常双128维持原资格 |
| 扩大已有粗档时间摘要范围或减少细时间段 | 热脉冲峰值、快速启停/开门的散热、相变时间更不精确 | 粗档追赶积压的工作减少 | 仅作用于已过载区域；不能越过结构/身份/保存边界，不把总J相同当作温度曲线相同 |
| 进一步延长恢复退避或提高恢复条件 | 压力消失后，细节和局部峰值更晚恢复 | 更少fine/coarse反复切换、试建与回收 | 初始沿用现有参数；实测频繁震荡后才调整，粗档必须持续推进 |
| 比原份额更严格地限制单区域并行子工作 | 一个大区域独占机器时的最快构建/求解时间可能变差 | 多区域同时繁忙时，更稳定的服务机会与更低候选峰值 | 优先在存在其他待服务区域时约束，空闲资源可按预算借用，不为固定上限浪费所有空闲核 |
| 比当前实际需求更保守地长期预留更多余量 | 同128MiB内能同时容纳的活动范围或候选减少 | 某些发布/保存/降级的容量等待减少 | 原设计本已预付必要空间；先补齐真实峰值，不新增无测量依据的大块预留 |
| 为频繁施工额外增加合并等待窗 | 门、墙和新热源的几何响应进一步变慢 | 更少失效候选和反复构建 | 非基础建议；只有频繁施工确实主导成本时另行衡量，不能自动放宽geometry_current和年龄条件 |

当前`RegionWorkPolicy`已经使用600tick起始恢复退避、失败倍增至9600tick；20TPS下相应计时为30秒到480秒，且还需满足其他恢复资格，不能把它当准确恢复时刻承诺。维持这些值并非新损失，延长才是新的取舍。

源聚合需要区分：在相同数值时间段、相同路由与权重下，合并输入到同一粗节点可以保持该粗模型的输入总量；源身份账目仍保留。这本身不要求新增近似。把不同时间段、不同结构或身份合并，才会增加时间/物理误差，不能混为一项优化。

## 四、实施成本与新的风险

| 成本或风险 | 对审查意味着什么 |
|---|---|
| 控制流程替换的回归面较大 | 接管、取消、相变、重建、保存和关闭必须同批核对，不能只替换入口而留旧消费者 |
| 输入权威更集中 | 共用入口的Bug可能同时影响fine与粗档；这是降低重复代码的对应风险，应使数据边界更直接而不是包进通用框架 |
| 缓存和索引增加 | 必须记录计费及具体失效条件，不能以“性能缓存”引入第二份需要同步的真实温场或J |
| 协调提交成为明显热点 | 原设计本已单处提交；要让准备工作留在worker/分片阶段，禁止在提交点全量复制/遍历，不是再加一层总锁 |
| 实际峰值可能与估计不同 | 统一所有权可能减少重复记账，也可能暴露漏计；不能预先承诺活动容量增加或内存下降 |
| 保留多核/自适应后仍有必要复杂度 | region合并拆分、相变ACK、worker退出和reader租约不会消失；改造需拿实际删除的控制状态/等待边说明收益，不能靠重命名宣称完成 |

## 五、审查与真实验收项目

| 场景 | 必须保留或证明 | 必须报告的代价 |
|---|---|---|
| 正常双128源与100消费者 | 原精度、原40tick/几何条件、FINE、正确查询 | 主线程/全热池CPU、实际年龄分布、构建和提交尾延迟、root/分配/GC；不拿平均数替代最长等待 |
| 同一真实region上千篝火，另有正常房间 | 验证源确实属于同一区域；实际粗档连续提交；正常房间持续服务 | 降级开始/完成时刻、粗档推进频率、输入/路由/几何/求解各自费用、预算拒绝与积压 |
| 停火或移除压力后 | 粗档继续推进，按资格恢复；交接不重复产热或回滚 | 恢复等待、fine候选CPU/内存、取消次数、同采样时间的恢复跳变 |
| 同Page不同源交错，源替换及开关门 | 源前缀接管不会被另一源未来段挡住；身份不串 | 输入保留量、队列等待、各阶段具体阻塞者及解除事件 |
| fine与粗档取消/重试、相变 | 相同输入只提交一次，旧身份不影响新方块；相关区域确实等真实依赖 | 重做费用、相变完成时间、任何新近似与原曲线差异 |
| 压力期间保存/卸载取消/独立JVM重载 | 一致截点及未消费J；当前格式正确恢复；在线输入不重复导出 | 捕获/复制/编码/IO费用与热主回调等待，不能只报告保存成功 |
| 关闭与仍持有旧读者/迟到helper | 所有者正确退出，最后读者释放后计费归零 | 退出耗时及残留；前一场景未释放的后续结果不得视为独立证据 |

全部使用真实Forge/游戏场景，不运行JUnit。原数值门槛不自动放宽；若用户另行选择某项近似，应将新旧指标并列报告，并保留原门槛下的结果。

## 推荐审查结论

先采用不主动削弱能力的基础控制重构：保留多核、粗档、恢复、正常事件时间顺序、正常精度和原资源上限。额外更早降级、扩大时间摘要、延长退避、收紧份额/增加余量/额外施工合并均不捆绑批准。

相对理想原设计，本次主要是让其所有权和进展规则真正成立，并减少达成这些目标所需的控制状态。相对当前实现，则预期减少交叉等待、重做和重复路由。两者不能混写成“新架构获得了原设计没有的多核和粗档”。量化收益和实际删除规模留待实施与真实测量。
