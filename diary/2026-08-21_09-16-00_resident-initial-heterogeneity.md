## Completed

- Extended `ResidentGenerationModel` so ordinary recruits independently generate health, mental state, four nutrition reserves, education, strength, intelligence and three work proficiencies in one reproducible profile.
- Added centered four-sample initial health, mental and nutrition distributions with default bounds `30..70`, plus configurable education weights `0.20/0.60/0.15/0.04/0.01/0.00` for levels `0..5`.
- Persisted `WanderingRefugee.ageDays`; tower batches, natural spawning and spawn eggs now initialize age and age-days through the same weighted entry point before recruitment.
- Routed wandering-refugee recruitment and `/town residents add <first> <last> [infant|child|adult|elder]` through `Resident#createRandomRecruit`. Citizen and AI-town debug constructors remain outside this change.
- Updated Stage 3/4 game-generated residents to use the same heterogeneous health, mental and per-channel nutrition profile, and extended Stage 0 parameter auditing.
- Updated `docs/town/town-model.md` and `docs/nutrition/nutrition-player-resident.md`; marked the previous fixed-health Monte Carlo conclusion stale.

## Decisions

- Reused the existing four-uniform-sample average so values concentrate around `50` while remaining within `30..70`.
- Treated the omitted sixth education probability as level-5 weight `0`, because the five supplied probabilities already sum to `1.0`; all six weights remain configurable.
- Kept cold-current quality as a tower-specific post-generation modifier, but intersected its health range with the ordinary bounds so old `20` configs cannot break the new minimum; the default cold range is now `30..40`.
- Legacy resident deserialization remains unchanged: missing nutrition still defaults to `70` and missing work-proficiency keys are generated by the existing migration path.
