## 选择

把逐格温度与焓、正负热输入归属、真实物理 tick、读者的 40 tick 有效期作为约束。对等效实现，比较热工作线程周期、瞬时分配与常驻内存、主线程尾延迟，以及需要长期维护的状态。优先保留在分散基地上能省工作、在连通建筑中能使用现有算法、且只依赖已有状态的改动。

| 职责 | 推荐粒度 | 更新时机 |
|---|---|---|
| 数值与采样时间 | 按 16³ Section 对应的 Tile 持有已提交帧和实际采样 tick；已分配的 4³ Brick 内逐格保存焓 | 按现有物理步和输入提交。存盘仍以已提交值及其实际时刻交接。 |
| 温区成员 | 按活动 Section 和真实依赖形成的成员集合，可沿用现在较保守的相邻关系 | Section 加入、退出、冻结、激活，以及跨区依赖的新增、失效、删除会影响成员。先处理能证明没有跨区连接变化的替换。 |
| 待处理几何的影响范围 | 延用每笔输入已有的 `RegionalContinuationBoundary` | 按已经改变的空间键判断旧范围是否仍有效。可能新增的通路从变化处重新发现，通路端点、相关热源及正在重入的区段都参加时间对齐。 |

材料换型、导热率和天空环境系数仍在各自生效 tick 更新。几何版本、温区成员变化和热源交接分别有自己的触发条件。`structureCommits` 同时参与恢复、热源与几何就绪判定，局部优化应在对应的缓存消费者上生效。

## 两处接入点

1. **温区成员。** `replaceTransport` 先发布新系数与环境边界。如果旧、新通路以及同次提交的路由有效性均可证明不会改变跨区依赖，复用已有成员。`AirRouteValidity.commit` / `retire` 能使原对象的 `activeForSolve()` 改变，端点恰好相等也要处理激活与退休。需要更新成员时先走现有 `domains()` 重建。阶段一只需复用成员，不新增每格邻接表、每 Brick 时钟或第二份热量所有权。
2. **几何影响范围。** 原型复用 `fixedBoundaries` 中现成的 Section 集合。对于已知的局部几何索引变化，依次检查每个变更区段和它的六个面邻区是否在旧范围里。相交则用原来的 `continuationBoundary` 重查，互不相交则沿用。允许一批报告多个变更区段。原来的种子和 3×3×3 邻区定义照常使用。对新的桥接区段，即使它原先不在范围中，它也会碰到旧范围的外沿，从而触发更新。这个检查额外占用的存储可以只是一份本次提交的变更 Section 列表。

第二项成立的前提是发布方完整列举**改变遍历结果的空间键**。来源包括旧、新 Page 与 halo 覆盖，通路草稿、已发现依赖与通路端点，热源起点和实际出口，以及重入时已声明的位置。成员、冻结和时间边界分别按对应合同更新。待发现通路的全局种子、未解析标记或影响范围未能完整列举的来源变化，采用现行完整刷新。原型已检验局部几何、跨两个新增区段的桥、拆桥与远端待发现通路。正式接入还需逐项核对热源出口的增删、转向、冻结与重入，尤其是新增出口仅在新关系中出现时。数值交换所需的范围和发现新通路时所需的范围可以不同。

## 何时值得细分

百人修复版第 20 tick 的 17 个完整温区中，170 对相邻 Section 都有 Brick 在对应位置接面。单靠 Brick 面接触筛选仍得到 17 个温区。三个只捕获同一局部角落的相邻 Section 则有真实的分离机会。先在稀疏建筑收集被误合并的域、受牵连的等待 tick 和实际多算的格面。若这些开销可观，使用现有 64 位 `activeBricks` 取得 Section 每个面上 4×4 个 Brick 的占用，作为廉价的接触筛选。需要更细时再为变更 Brick 考虑每面 16 个格位的摘要、实际材料接触与导热规则。风道远端和热源角点分配的相关 Section 须同时纳入。长期保有每格图或改变存档时钟会增加状态和提交成本，当前负载优先验证前两项。

## 验收与结果

生产接入时在相同的几何与时钟上比较每次所得的完整 Section 集合、待发现路由标记、最终跨区出口和温区成员。用隔开的基地、连续大建筑、开洞接通及封堵断开、带正负热的区块卸载重入覆盖物理时序。最终比较每格温度及焓、实际 sampleTick、输入交接次数和能量账。固定工作用原生线程周期与每线程分配，百人负载用同一套场景、读数及时/过期/缺失、工作线程周期、主线程 P99 和内存预算对照。

百人旁路观测在 1,400 tick 内记录了 16,787 次写入影响范围缓存。3,600 次是当时首见的待处理输入。其余 13,187 次中有 13,177 次得到相同的区段集合与路由状态，10 次得到不同结果。温区成员实际重建 797 次，首份无前值，其余 796 次中有 667 次成员分组与前一次完全相同。重复结果说明值得投资的路径；能否提前复用依赖发布方报告的空间变化。

在已测 17 个温区的空间坐标上进行受控增删，局部候选和全量算法的 13,872 个结果逐项相同，局部候选重新搜索 816 次。单一连通建筑对照中的 10,368 次搜索均需执行。另取每组 32 个相同增删事件计时，分散布局中该阶段的线程周期配对中位数下降 93.57%，累计分配约 2.75 MB 降至 0.15 MB。单一连通建筑的周期接近，分配的配对中位变化为零。成员复用定向对照覆盖空通路、仅环境边界和真实跨区通路的增删。完整服务器 CPU 收益要以接入生产触发条件后的候选版计量。

已经完成的 CPU 对照与服务器旁路计数保存在[本次验证](../docs/climate/validation/thermal-validation-data-2026-11-19-to-20.json#/records/thermal-spatial-dependency-2026-11-19)。原型运行于测试目录，现行数值与生产调度见[运行时控制合同](../docs/climate/thermal-runtime-control.md)。

## 生产接入结果

`PendingGeometryBoundaries` 复用原始几何影响范围，`WorkerPhysicalSourceBindings` 单独跟踪可能跨 Section 的实际出口。`TiledThermalField` 根据维度内还有无持有路由对的 Tile 决定是否需要重建温区成员。分散布局完成等量编辑时，生产边界维护的线程周期配对中位数降低 90.78%。单一连通布局的所有搜索均须执行。包含桥接、回滚、出口换向和路由退休在内的 68 项 Forge 用例通过。

同启动器的百人基线取得 5,155 次及时读数。后台 Java 活跃及安静时，同一候选分别取得 3,224 及 5,589 次。安静对照中原生周期下降 14.78%，观测工作线程 CPU 从 1,406.25 增至 1,750 ms。两次实际启用热源序列存在差异。固定场景的几何优化已验证，整服稳定 CPU 收益与长时间运行资格仍待后续负载验证。详见[运行回执](../docs/climate/validation/thermal-validation-data-2026-11-19-to-20.json#/records/thermal-local-topology-runtime-2026-11-20)和[开发日记](../diary/2026-11-20_03-02-02_thermal-runtime-and-material-history.md#thermal-local-topology-runtime)。
