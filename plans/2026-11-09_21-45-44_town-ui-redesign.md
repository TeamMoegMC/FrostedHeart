## 目标

项目所有者的需求（2026-11-09）：

- 现在的城镇界面比较原始：几乎全靠文字描述展示内容，界面很小，没有好看的背景。
- 重新设计一套更适合普通玩家理解的界面，只展示最直观、最重要的信息，尽量减少小数。
- 保留一个调试开关，可以在游戏里用指令调节，需要管理员权限。开启后展示完整的全部信息。
- 先做设计，不实现。设计已定稿，决定见下一节。

## 已核实的现状

以 2026-11-09 工作区（含未提交改动）为准。路径省略 `src/main/java/com/teammoeg/frostedheart/` 前缀。

- **尺寸固定。** 建筑界面统一 176×222（`content/town/AbstractTownWorkerBlockScreen.java:66,152-155`），镇长印章 264×222（`item/townmanager/TownManagerScreen.java:62-88`）。包装器只负责居中，没有任何界面随窗口缩放。CUI 里唯一随窗口变化的先例是研究札记（`DrawDeskScreen.resizeKnowledgeToWindow` 加 `KnowledgeLayout` 宽度断点）。
- **一半面积给了用不到的背包。** `townworkerblock.png` 下方 90 像素是烤进贴图的玩家背包，每个建筑菜单都在 y=140 加入背包槽位，但只有仓库真的用到物品（例如 `MineBaseMenu:37-38`）。建筑信息因此全部挤在 (8,4) 处 160×130 的一个框里，一屏约 8 行。
- **信息框是深灰色填充，没有贴图。** `TownInfoPanel` 用 `0xE0101010` 填充加 1 像素描边（`content/town/tabs/TownInfoPanel.java:295-303`），同样的画框代码在各面板里复制了约 11 份，行高有 12、13、14 三种。
- **最长的文字墙。** 住宅居民面板约 33 行挤在 9 行里；镇长印章「村民」页约 32 行；研究所概览与研究页 20–30 行；印章总览约 25 行。居民营养说明一项就有 15 行，其中 10 行是 `%+.2f`（`ResidentNutritionExplanation:42-109`）。
- **小数最多的地方。** 营养说明（`%+.2f`）、员工卡（生产力 `%.2f`、熟练度增长 `%+.1f`、个人贡献 `%.1f`/`%.2f`）、采矿生产（9 行以上 `%.1f`）、住宅餐食（最多 4 位小数）、狩猎质量（3 行 `%.1f%`）、住宅温度失败行里直接显示配置的 Double 阈值（`10.0`）。
- **同一个量格式不一。** 食物消耗 `%.1f` 与最多 4 位；舒适度 `%.1f%`、`%.0f%`、整数百分比三种；研究人力向下取整与 `%.2f` 两种；居民属性「x / 100」与 ■ 条两种；「°C」前有时有空格；中文里半角「: 」与全角「：」混用。
- **原始键名和内部信息直接给玩家。** 运输端点类型 `P2P_DIRECT_LINK`、设备状态 `REDSTONE_PAUSED` / `UNAVAILABLE`、8 种 `NUTRITION_*` 事件没有翻译（`TownVirtualResourcesPanel:405-418`、`TownSignalEvent:89-96`）；设备行显示维度 ID；建筑之间只能靠原始坐标区分（印章建筑列表是一排同名的「住宅」）。
- **命名漂移。** 「村民」与「居民」、「城镇方块」与「建筑」、方块名「矿工之家 / 猎人之家」与界面名「采矿基地 / 狩猎基地」并存。
- **可以复用的东西。** CUI 有面板、换行文本、文档式流排版（`ContentPanel`）、按钮、标签页、滚动条、物品图标和九宫格图标（`chorda/client/icon/CIcons.java:458,728`）以及主题机制（`chorda/client/cui/theme/Theme.java`）。研究札记的羊皮纸来自 `draw_desk.png` / `escritoire.png` 的九宫格区域，发电机界面有一整套蓝钢风格贴图（`general_generator.png`）。CUI 没有进度条控件。
- **没有可用的界面调试开关。** `ITown.DEBUG_MODE` 是编译期常量 `false`，管玩法（`content/town/ITown.java:33`）；F12 是 CUI 控件检查器；`FHConfig.Client` 没有调试项；也没有按玩家同步设置的通用数据包。客户端已经知道玩家的权限等级（`frostedresearch/gui/drawdesk/CardButton.java:90` 用过 `hasPermissions(2)`）。

## 决定

项目所有者 2026-11-09 对起草时六个问题的答复：

1. **详细模式按玩家。** 管理员只打开自己或指定玩家的详细模式，不影响其他人。
2. **视觉风格：木板底加布告纸。** 界面的底是一块木板，信息卡是钉在板上的布告纸。它做成 CUI 的一个主题 `NoticeBoardTheme`：城镇界面都用它，别的界面以后也可以选用。见「视觉与布局」。
3. **调试信息单独成页。** 详细模式下每个建筑界面和镇长印章多出一个「调试」标签页，玩家视图本身不变。
4. **统一叫「采矿基地」「狩猎基地」。** 英文已经是 Mining Base / Hunting Base，界面也已经这样叫，只需要改两个中文方块名：`block.frostedheart.mine_base`（矿工之家，`zh_cn.json` 第 1157 行）和 `block.frostedheart.hunting_base`（猎人之家，第 1078 行）。实施时还要查一遍配套整合包的任务书和指南里有没有写死的旧名。
5. **建筑名称默认是自动编号加方位，玩家可以在界面里改名。** 见「建筑名称」。
6. **贴图先程序生成。** 用脚本生成占位贴图，界面结构做完后，再由美术按同样的尺寸和九宫格边距替换。
7. **布告板组合三个方向（同日追加）。** 对比过「霜封告示」「镇印公文」「营地生活板」三个方向后，项目所有者决定组合使用：
   - 霜表示冷暖。
   - 镇印与状态印戳表示身份和状态。
   - 照片与居民留言表示人。

   研究所按组合后的主题完整设计，见「研究所（样板）完整设计」。
8. **玩家视图用「人手」代替「标准工人 / 标准研究员 / 研究人力」（同日追加）。** 系统本身不变：内部照旧按标准工人折算个人效率。玩家看到的只换词：
   - 按效率折算后的能力叫「人手」，向下取整，例如「研究人手 2」。
   - 个人只说「效率 120%」。
   - 需求写成「要 2 个人手，干 2 天」，进度用百分比和天数。
   - 「人·天」不在玩家视图出现；调试页保留「标准工人」和小数。
   - 同时按「文案规则」去掉翻译腔、压短句子。

## 设计原则

1. **一眼三问。** 每个建筑界面按顺序回答：它在工作吗？它为城镇提供了什么？我能做什么让它更好？状态、产出、建议三块永远在同样的位置。
2. **问题优先于数据。** 能工作的条件（温度、照明、面积、人手）平时缩成一排勾选标记；只有不满足的那一条展开，并说明怎么修（「再放 1 盏灯」「需要供暖」），不把阈值公式摆给玩家。
3. **图标与条形图代替句子。** 数量用物品图标加整数，比例用进度条，质量用星级或等级词。一行文字只说一件事。
4. **整数优先。** 玩家视图里不出现小数（数字规则见下）；小数、配置阈值、内部系数只在调试视图出现。
5. **调试视图不丢信息。** 现有界面的全部行原样保留为调试视图，玩家视图是在它之上新做的一层。这样改版不会让开发和排错失去任何数据，也降低了改版风险。
6. **同一套组件，同一种手感。** 所有建筑和镇长印章用同一组卡片、标签、进度条、居民头像；同类信息在每个界面的位置和颜色都一样。
7. **服务沉浸感。** 界面像镇上的告示板：布告纸钉在木板上，深色字印在浅色纸上。它和研究札记的纸张同属一个家族，也和寒冷的室外形成对比。

## 信息分层

| 层 | 谁看 | 内容 |
|---|---|---|
| 玩家视图（默认） | 所有玩家 | 状态、1–4 个关键数字、需要处理的问题和建议、工人头像与一句话状态 |
| 展开详情（玩家可点） | 所有玩家 | 某个关键数字的构成，仍用整数、百分比和等级词，例如「研究人手 2：博士 1 个，初等教育 1 个」 |
| 调试视图（管理员开关） | 开启了详细模式的管理员 | 现有全部行：原始小数、阈值、预测与实际结算、每级人力、停工原因代码、配置值 |

## 数字规则（玩家视图）

| 类别 | 规则 | 例子（现在 → 改后） |
|---|---|---|
| 计数（人数、方块数、天数） | 整数 | 不变 |
| 按效率折算的人手与产出（人手、运力、捕猎、开采） | 向下取整的整数；不足 1 时写「不足 1」 | `1.19 名标准研究员` → `研究人手 1` |
| 个人效率、产出倍率 | 整数百分比 | `预计个人研究人力：1.20 名标准研究员` → `效率 120%` |
| 质量与评分（装饰、空间、温度质量） | 五档等级词加星级（简陋/一般/舒适/优良/精美）；调试视图保留百分比 | `装饰：37%（研究人力 +11%）` → `装饰 ★★☆☆☆ 一般` |
| 温度 | 整数 °C，配合「合适 / 偏冷 / 太冷」颜色；不合格时向不利方向取整（低于下限向下取整，高于上限向上取整），合格时四舍五入 | `有效室温：9.9°C（至少 10.0°C）` → `太冷 9°C（需要 10°C）` |
| 照明 | 等级词：昏暗 / 够亮 / 明亮 | `平均灯光：12.8（至少 8.0）` → `够亮` |
| 进度（人·天、研究进度） | 进度条加整数百分比或「第 x/y 天」 | `已投入 3.57/4.00 人·天` → `▓▓▓▓▓▓▓▓░ 89%` |
| 仓库物品 | 向下取整的整数；少于 1 显示「少量」 | `paper 56.47` → `56` |
| 居民属性 | 0–100 的整数条 | 不变，统一成条形 |

边界规则：

- 合格判断永远用原始值，显示的整数只是标签。离阈值只差一点时（例如 9.9 °C 对 10 °C），文字必须跟着判断走，不能出现「10°C 但不能工作」。
- 向下取整用于「能力」（不夸大），进度用向下取整的百分比（不提前显示 100%），只有完成时才显示 100%。
- 同一个量在所有界面用同一个格式函数，避免研究所显示 1.2、札记显示 1.1 这种不一致。

## 组件

所有城镇界面共用一组组件。玩家视图只由这些组件拼成，不再直接堆文字行。

| 组件 | 作用 | 说明 |
|---|---|---|
| 页头 `Header` | 建筑图标、名称、状态标签 | 状态标签三色：绿「运转中」、黄「受限」（能工作但有短板）、红「停工」；悬停给出原因 |
| 关键数字 `StatTile` | 一个图标、一个整数、一个短标签 | 每屏 1–4 个；图标优先用现成物品（面包、纸、书架、篝火），不必先画新图 |
| 条件标记 `CheckChip` | 工作条件一项一个 | 满足时是小勾；不满足时变红并展开成一行「怎么修」 |
| 便签叠 `NoteStack` | 一叠可以翻的便签：先是改进便签，再是居民留言 | 每张改进便签一句居民的话加一行「→ 怎么做」；点击像掀纸一样翻到下一张；规则见「研究所（样板）完整设计 · 便签叠」 |
| 进度条 `ProgressBar` | 进度、容量、库存占用 | 只配整数百分比或「x/y」 |
| 居民条 `ResidentRow` | 头像、名字、职业或教育徽章、效率百分比 | 点开看属性条；调试视图追加原始属性与熟练度小数 |
| 等级 `Rating` | 五档星级加等级词 | 装饰、空间、温度质量、住房舒适度共用 |
| 详细模式徽标 `DebugBadge` | 页头右上角的「调试」小标 | 只在详细模式出现，提醒当前看到的是完整数据 |

## 视觉与布局

- **主题：木板底加布告纸（`NoticeBoardTheme`），组合三个元素。**
  - **木板与布告纸。** 窗口底是一块横纹木板，四角有钉子，板顶常年积着一道雪和几根冰凌。信息卡是钉在板上或用胶带贴住的米白布告纸，可以有极轻微的倾斜。
  - **霜：冷暖。** 主告示和居民照片按温度结霜：暖时纸面干净，接近停工线时角上起霜，低于停工线时纸边结满霜并挂冰凌。玩家不读字也能看出哪里冷。
  - **镇印与印戳：身份和状态。** 页头告示右侧盖本镇的方形红印，印文取镇名；状态用一枚倾斜的印戳：绿「运转」、黄「受限」、红「停工」。任务单上用「完成」「缺料」「停」印戳。
  - **照片与留言：人。** 研究员、居民以钉在板上的照片出现；建议写在一叠可以翻的便签上，每张是一句居民留言加一行明确的做法，署居民在游戏里的名字。
  - **标签页**是钉在木板左缘的小木牌，选中的那块向外抽出；调试页的木牌是红色，只在详细模式出现。按钮是小块纸签。
  - 主题提供以上全部九宫格贴图，组件只向主题要贴图，不各自画框。贴图清单见「研究所（样板）完整设计」。
- **贴图来源。** 占位贴图由脚本 `Scripts/gen_town_ui_textures.py` 生成到 `assets/frostedheart/textures/gui/town/`。脚本里写明每张图的尺寸和九宫格边距，美术替换时照此出图。
- **尺寸随窗口变化。** 内容区宽度在 320–480 GUI 像素之间随窗口缩放，高度在 200–300 之间，不再固定为 160×130。427×240（1280×720、界面尺寸 3）是最小目标尺寸，在它上面所有玩家视图必须不滚动就能看到状态和关键数字。
- **玩家背包。** 只有需要放物品的界面（例如仓库接口）才显示背包；纯信息界面不再占用下半屏。
- **标签页。** 左侧图标标签保留。每个建筑一般三页：概览、工人、专项（研究、运输、狩猎、开采各自的产出页）；研究所因为有联想多一页。详细模式下的调试页另算。

## 详细模式开关

现有的调试开关都不合适：`ITown.DEBUG_MODE` 是编译期常量，而且管的是玩法（居民不死、跳过有效性检查）；F12 的 CUI 检查器只画控件边框；`FHConfig.Client` 没有调试项。所以新增一个只管界面显示的开关，叫「界面详细模式」，和玩法调试分开命名。

- **指令。** `/town ui detailed [on|off] [玩家]`，同时挂在 `/frostedheart town …`、`/twr town …` 下，沿用 `TownCommand` 的 `requires(s -> s.hasPermission(2))`。不带参数时报告当前状态；不写玩家时作用于自己。
- **范围：按玩家（已决定）。** 管理员打开的只是自己（或指定玩家）的详细模式，不影响服务器上其他玩家。
- **保存。** 存在玩家的持久数据里，重新登录后保持。登录时如果该玩家已经没有 2 级权限，服务器清除标记，避免被撤销管理员的玩家继续看到调试数据。
- **同步。** 新增一个很小的服务器到客户端数据包 `TownUiModeS2CPacket(boolean detailed)`，登录时和指令切换时各发一次；`FHNetwork` 的协议字符串随之升级。客户端存入 `TownUiMode`，已打开的城镇界面收到变化后立即重建。
- **显示。** 详细模式下页头出现「调试」徽标；每个建筑多出一页「调试」，内容就是现在的全部文字行（原始小数、阈值、预测与实际结算、每级数值、停工原因代码）。玩家视图本身不变，方便对照。
- **不需要额外数据。** 现在客户端已经收到完整的建筑记录，调试页只是多渲染一些行，服务器不必为详细模式另发数据。

## 建筑名称

- **默认名。** 格式是「类型 + 编号 + 方位」，例如「住宅 3 号 · 西北」。
  - 编号按类型分别计，从 1 开始，在建筑登记时分配并保存。拆掉一座不会让别的建筑改号；新建的取当前最小的空号。
  - 方位是相对能量塔的八个方向（北、东北、东……），离能量塔很近（建议 16 格内）时写「中心」，城镇没有能量塔时只写编号。方位每次显示时现算，不保存。
- **改名。** 建筑界面的页头、镇长印章建筑页的名称旁各有一个笔形按钮，点开就地编辑；清空即恢复默认名。
  - 新增服务器数据包 `TownBuildingRenameC2SPacket(pos, name)`。服务器检查玩家属于这个城镇的队伍，去掉格式符号，限制长度（建议 16 个字符以内），然后保存，并随城镇数据同步给所有成员。
- **保存位置。** 城镇数据里新增一张「建筑位置 → 编号与自定义名」的表，各建筑自己的编解码器不用改。建筑拆除时一并移除；旧存档没有这张表时，登记顺序决定初始编号。
- **使用位置。** 页头、镇长印章的建筑列表、居民的住处与岗位、事件记录、「需要处理」列表都用这个名字，玩家视图里不再出现裸坐标，坐标只在调试页。

## 实现结构

把「算出要显示什么」和「怎么画」分开：

1. **格式函数 `TownFormat`（通用代码，纯函数）。** 每类数字一个函数：计数、能力（向下取整）、效率百分比、等级（五档）、温度状态、照明状态、进度百分比、库存数量。返回 `Component`，所有界面共用，GameTest 可以直接测边界。
2. **展示模型（每种建筑一个 presenter，纯函数）。** 从建筑记录和预测生成 `BuildingView`：状态、关键数字、条件标记、建议、各页的分区。它不依赖客户端类，可以在 GameTest 里断言「玩家视图里没有小数点」「9.9 °C 显示为太冷」。
3. **组件与主题（客户端）。** 在 CUI 上新增 `NoticeBoardTheme`（实现 `chorda/client/cui/theme/Theme`，提供木板、纸张、纸签按钮、标签木牌、进度条槽等九宫格贴图）和上面列出的组件。CUI 目前没有进度条控件，需要新做一个。
4. **自适应布局 `TownScreenLayout`。** 参照研究札记的做法：`DrawDeskScreen.resizeKnowledgeToWindow` 每帧把尺寸夹在窗口减边距之内，`KnowledgeLayout` 按宽度断点切换列宽。城镇界面换成同样的方式，不再固定 176×222。
5. **调试页。** 现有的 `overviewRows`、`researchRows` 等函数几乎原样搬进调试页，作为完整信息的唯一出处。

## 各界面的玩家视图

### 工作建筑的共用模板

研究所、狩猎基地、采矿基地、货运站共用一个模板，住宅和仓库在它上面增减。

- **概览页。** 从上到下依次是：
  1. 页头（建筑名与状态标签）。
  2. 2–4 个关键数字。
  3. 一排条件标记（空间、温度、照明、人手，按建筑取用）。
  4. 便签叠（改进便签在前，居民留言在后）。

  停工时，红色状态下面直接写第一条原因和修法，例如「太冷：通上暖气，或把房间改小」。面积、体积等原始数字只放在调试页。
- **员工页（替代 `TownWorkforcePanel`）。**
  - 每名员工一行：头像、名字、教育或职业徽章、效率百分比、状态（在岗 / 病了 / 没地方住）。
  - 点开一行看生命、精神、力量、智力四条 0–100 的条，和这份工作的熟练度条。
  - 熟练度增长用箭头加整数表示（「熟练度 ↑」），具体的 `%+.1f` 放到调试页。
- **专项页。** 「明天预计」和「上次结算」两张卡，每张都是物品图标加整数，异常（仓库满、物资缺、矿藏耗尽）用黄色提示条单独列出。

### 各建筑

| 建筑 | 关键数字（玩家视图） | 条件标记 | 典型建议 | 移到调试页的 |
|---|---|---|---|---|
| 研究所 | 研究员 x/y、研究人手（整数）、知识容量（档案、来件用量）、今天的联想 | 空间、温度、照明、人手、装饰星级 | 「再放张绘图台」「装饰到三星，人手多约 6%」「多点几盏灯」 | 每级人力小数、平均灯光数值、阈值、每人地面格数、装饰百分比与倍率、预测与结算的原始值、联想概率 |
| 狩猎基地 | 猎人 x/y、明天预计捕猎次数（整数）、上次战利品（图标） | 空间、温度、人手 | 「太冷，猎人出不了工」 | 三项质量百分比、生产力小数、预计次数小数 |
| 采矿基地 | 矿工 x/y、明天预计开采（整数）、已连接矿井 n | 空间、人手、矿井连接 | 「仓库快满了，上次丢了 n 个」 | 生产力、计划与可开采量小数、逐项 `%.1f` |

| 货运站 | 货运员 x/y、提供运力（整数）、城镇运力「已用 / 总计」条 | 空间、人手 | 「运力不够，n 台设备在等」 | 生产力、计划与实际运力小数 |
| 住宅 | 居民 x/y（头像）、吃饱程度（满足 / 不足）、舒适度星级、室温状态 | 空间、温度 | 「太冷：通上暖气」「吃的只够约 n 天了」 | 五项舒适度百分比、食物消耗小数、温度阈值 |
| 仓库 | 容量条「已用 / 总计」、物品种类数 | 空间 | 「仓库快满了」 | 精确容积、面积、体积 |

住宅另有两页：

- **居民页：** 用共用居民行。营养从 15 行说明换成四条营养条，加一句「最缺蛋白质」；生命与精神的明日变化只用 ↑ / → / ↓。
- **餐食页：** 物品格子只显示整数个数，「实际消耗」悬停提示也取整。

仓库库存格里的大数字用整数缩写：999 以内照写，1000 以上写成「1k」「12k」「123k」「1M」，不再出现「1.2k」。

### 研究所（样板）完整设计

示意图已在设计对话中与项目所有者确认：组合主题的三种状态；概览、研究员、协作研究、联想四页；详细模式下的调试页。联想原本是研究页底部的一张卡，知识容量原本也有单独一张卡，项目所有者认为它们和协作研究无关：联想改成单独一页，知识容量并进概览页的关键数字。

#### 尺寸与布局

以最小目标 427×240 GUI 像素为准，更大的窗口按比例放宽：

- **整体。** 外边距 6；木板左侧是 28 宽的木牌标签列（木牌 26×22，间距 3）；木板最小 387×228，带 4 像素边框和 6 像素内边距，内容区最小 371×212。窗口更大时，木板宽在 387–560、高在 228–340 之间变化。
- **页头告示。** 每页都有，横跨内容区。概览页高 30，其余页是 24 的窄版。
- **概览页。**
  - 页头下面是 4 张关键数字纸片，高 44，宽依次约 76、76、128、76，间距 5。知识容量那张加宽，放档案、来件两条用量条。
  - 再下面左边是 210×122 的「工作条件 + 协作中的研究」告示，右边是 152×122 的便签叠，下面露出后两张便签的边。
- **研究员页。** 左侧是照片墙：照片 48×56 加名字，最小尺寸下 2 列，窗口更宽时 3 列，超出就滚动。右侧是约 240 宽的人事卡。
- **协作研究页。** 任务单列表可以滚动，每张约 44 高，最小尺寸下约能看到三张半；底部一行写闲着的人手。
- **联想页。** 左边约 210 宽，是今天的结果告示（约 210×100）和今天琢磨的研究员照片。右边约 150 宽，是机会和研究所想到过的想法（可滚动）。
- **调试页。** 一整张方格纸的检修记录，可以滚动，右上角有「复制全部」。

#### 页头告示

- **名称**：「研究所 1 号 · 中心」，旁边是改名笔形按钮。
- **副行**：「研字第 1 号 · 雪松镇第 12 日」。每类建筑有自己的「字」：住、仓、猎、矿、运、研；编号就是建筑编号。
- **状态印戳**：运转、受限或停工，规则见下；悬停列出全部原因。
- **镇印**：方形红印，印文是镇名的前两个字加「镇印」，从右往左竖排。镇名改了，印文跟着变。
- **霜冻等级**：设 m = 有效室温 − 最低工作温度，按 m 取等级：

  | 等级 | m 的范围 | 样子 |
  |---|---|---|
  | 0 | m ≥ 5 | 纸面干净 |
  | 1 | 0 ≤ m < 5 | 两角起霜 |
  | 2 | −5 ≤ m < 0 | 纸边结霜，挂几根冰凌 |
  | 3 | m < −5 | 大片结霜，挂满冰凌 |

  能否工作仍按原始值判断，霜只是表现。

#### 状态规则

- **停工（红）：** 不能工作（结构、面积、体积、温度、照明任一不满足），或者明天预计人手为 0（没有能干活的研究员）。
- **受限（黄）：** 能工作，但有任一短板：岗位没坐满；有研究员干不了活；霜冻等级为 1；照明离下限不到 2；绘图台比面积允许的人数多。
- **运转（绿）：** 其余情况。

#### 概览页

- **四张关键数字：**

  | 纸片 | 大字 | 小字 |
  |---|---|---|
  | 研究员 | 在岗 / 岗位，例如「2 / 3」 | 有人不在岗时写原因，例如「1 人病了」 |
  | 研究人手 | 明天预计的人手，向下取整 | 「按效率折算」 |
  | 知识容量 | 档案、来件各一条用量条和「已用 / 上限」 | 标题旁写「书架 12」 |
  | 联想 | 想到了 / 有头绪 / 没想出 / 没人想 | 点击进联想页 |

  知识容量的悬停说明：「12 个书架给全队加了档案 192、来件 48。停工就没了。」
- **工作条件：** 四个标记：空间够 n 人、室温（带状态词）、照明等级、装饰星级。下面列出最多 4 项协作中的研究，各一条进度条；停着的那项标红。
- **便签叠：** 规则见下。

#### 便签叠（改进与留言）

右下角是一叠可以翻的便签，既明确告诉玩家该改什么，又带着居民的口吻。

- **两种便签。**
  - **改进便签：** 黄色，标「可以改进」。第一行是居民说的话，第二行是「→ 做法」，动词开头，带上关键数字，例如：

    > 屋里冷，再冷两度就干不了了。
    >
    > → 通上暖气，保持 10°C 以上
    >
    > —— Gabriel

  - **留言：** 白色，标「留言」，只有居民说的话。
- **顺序：第一张是定的，不随机。** 每次打开界面：
  1. 改进便签按下面的优先级排在最前，最多 3 张。
  2. 后面是留言，打乱顺序，补到总共最多 6 张。
  3. 没有要改进的，整叠都是留言，随机从一张开始。

  这样「要停工了」永远在最上面；随机只用在闲话上。
- **翻页。**
  - 点击便签或右下角的折角，或在便签上滚动滚轮，最上面一张掀起来（约 0.2 秒）落到最底下。翻到最后回到第一张。
  - 键盘焦点在便签叠上时，回车和空格也能翻。
  - 不自动轮转，免得玩家读到一半内容被换掉。
  - 打开约 2 秒后，折角轻轻掀一下，提示可以翻；底下露出后两张的边，右上角写「1 / 6」。
- **「新」印戳。** 上次打开以后才出现的问题，盖一个红色小「新」，翻过一次就消失。「看过哪些问题」记在客户端内存里，按建筑位置和问题种类区分，退出游戏清空。
- **署名。** 取一名在岗研究员；问题出在某人身上时，由同事署名；没有研究员时署「备忘」。

改进便签的优先级（同时成立时取前 3 条）：

| # | 条件 | 居民说的话 | 做法 |
|---|---|---|---|
| 1 | 温度不合格或霜冻等级 1 | 屋里冷，再冷两度就干不了了。 / 太冷了，手都伸不开。 | 通上暖气，保持 10°C 以上 |
| 2 | 照明不合格 | 太暗了，图纸都看不清。 | 多点几盏灯 |
| 3 | 结构、面积或体积不合格 | 写哪里不合格 | 写修法 |
| 4 | 有研究员干不了活 | William 病了，他家（住宅 2 号）太冷。 | 给住宅 2 号通上暖气 |
| 5 | 档案或来件用到九成以上 | 来件快塞不下了。 | 去札记整理来件，或多放几个书架（每个来件 +4、档案 +16） |
| 6 | 面积限制了人数 | 太挤了。 | 再腾出约 n 格地，能多坐 1 人 |
| 7 | 面积够但绘图台不够 | 还有地方。 | 再放张绘图台，能多 1 人 |
| 8 | 有协作研究或联想因学历停着 | 缺个念过中学的，信号推演动不了。 | 招个中等教育以上的居民 |
| 9 | 装饰低于三星 | 屋里太素了。 | 摆些讲台、花盆、旗帜，到三星人手多约 n% |

第 4 条的原因从这个人住处的温度、吃饱没有和营养主要缺口里挑影响最大的一项。书架数值和温度下限取自配置，不写死。

留言按当前状态挑，每类准备几句随机用：

- 研究快完成了：「烧窑记录快理完了，明天大概能出结果。」
- 今天想到了点子：「昨晚想到个点子：回应的回声！」
- 屋里暖和：「炉子边暖和，画图都快了。」
- 书架、装饰多了：「书架又满一格，像样了。」
- 没有特别的事：日常闲话。

#### 研究员页

- 页首一行：「研究人手 2（未受教育 1，初等教育 1）」。
- **照片墙。**
  - 每个分到研究所的居民一张照片（先用首字母色块占位，以后换成头像），点击选中。
  - 不在岗的照片盖「休养」或「歇工」印戳；他家的霜冻等级也画在照片上。
  - 岗位没坐满时显示虚线空位，写「闲着的居民会自动补上」；坐满时写「3 张绘图台都有人了」。
- **人事卡（选中的人）。**
  - 卡头：名字、教育徽章、「效率 104%」、「在岗 / 休养」印戳。效率是这个人折合的人手 × 100%，向下取整；悬停写「效率 100% 算 1 个人手」。
  - 五条整数属性条：生命、精神、力量、智力（标「主要」）、研究熟练。
  - 三句话：「干完今天：智力 ↑ 研究熟练 ↑」「能接：初等教育以下的研究」「住住宅 1 号 · 北，暖和」。

#### 协作研究页

- 页首一行：「今天 2 个人手 · 学历要求高的先派」。分配规则的完整说明放在这行的悬停提示里。
- **任务单：** 每项带人手协作的研究需求一张。
  - 标题行：类型图标、「项目 · 需求」、「必须协作 / 可代劳」标签，右侧是百分比和「还差约 n 天」（可代劳的写「攒满抵一次试验」）。
  - 下面是进度条，再下面一行：「要 2 个人手，干 2 天」「每天：纸 2、木炭 1 · 仓库够 28 天」「今天 +26%」。
  - 问题写在同一行：人手不够写「人手不够，只做了一半」，物资不够写「木板不够，只做了一部分」。
  - 印戳：物资不够盖黄色「缺料」；没有够学历的人盖红色「停」，写「要中等教育以上的人，现在没有」；完成后收成一行，盖绿色「完成」。
  - 点击任务单打开研究札记的对应项目。
- **闲着的人手：** 底部一行「还剩约 n 个人手闲着，去联想 →」（向下取整，不足 1 写「不足 1 个」），点击进联想页。这是协作研究和联想之间唯一的连接：协作研究先占人手，剩下的才去联想。

#### 联想页

- **页首一句：** 「每天早上，闲着的研究员会琢磨档案（要中等教育以上）。」
- **今天的结果（黄色便签告示）。** 按日报的结果分五种：

  | 结果 | 告示 |
  |---|---|
  | 想到新想法 | 大字写想法名；下面「由「A」和「B」想到」；盖「新想法」印戳；「去札记看看 →」 |
  | 有了头绪 | 「对「主题」有点头绪了」；「去札记看提示 →」 |
  | 没想出 | 「想了一早上，没想出来。」加上机会 |
  | 想不出新东西 | 「手头的知识想不出新东西了。」→ 多去收集些观察 |
  | 没人琢磨 | 「今天没人琢磨」加原因（没有中等教育以上的人，或人手都派去协作研究了）→ 招个中等教育以上的居民 |

- **今天琢磨的人：** 照片和教育徽章，加上「闲着的人手约 n 个」（向下取整）。
- **机会：** 五格刻度加一个词，按最近一次清晨闲着的合格人手和配置的联想速率换算。概率 20% 以下是很低，20–40% 较低，40–60% 一般，60–80% 较高，80% 以上很高；百分比只在调试页显示。悬停说明：「闲着的中等教育研究员越多，机会越大。协作研究会先占人手。」
- **研究所想到过的：** 想法名和城镇日，最新的在上，点击在札记里打开。

#### 调试页（详细模式）

- 红色木牌标签，内容是方格纸上的「检修记录 · 建筑名」，分「概览」「研究员」「协作研究」「联想」四段。
- 内容就是现在三页的全部行，沿用内部说法：标准工人、人·天、原始小数、阈值、预测、教育等级、联想概率和结果代码、容量基础值。
- 右上角「复制全部」把全文复制到剪贴板，方便报告问题。

#### 交互与动效

- **改名：** 点笔形按钮，名称变成输入框；回车保存，Esc 取消，清空恢复默认名。
- **悬停：** 关键数字、状态印戳和条件标记都有悬停说明，也只用整数和等级词。
- **打开界面时：** 霜在约 0.6 秒内从上次看到的等级过渡到现在的等级，变暖时是化开。
- **状态变化时：** 印戳「盖下」一次，配一声盖章音（占位用原版音效）。
- **切换标签页：** 木牌抽出，配翻纸声。
- **便签叠：** 掀起一张约 0.2 秒，配轻微的纸声；打开约 2 秒后折角提示一次。

居民页的细节：

- **列表。** 每人有一个状态点（红：有风险，黄：值得留意，绿：正常，灰：儿童等不工作的人）和职业图标；有问题的排在前面。上方是搜索框和带人数的筛选标签（有风险 / 没工作 / 没住处）。
- **详情。** 先是一条原因横幅，例如「病了，歇工中：家里太冷，缺蛋白质」。原因从住处温度、吃饱程度和营养主要限制里挑影响最大的一两项，这些数据客户端都已有。
  - 住处与岗位用建筑名，旁边的「定位」跳到建筑页的那座建筑。
  - 四条身体属性带趋势箭头，四条营养（碳水、蛋白质、蔬菜、脂肪）后面跟一句可执行的建议，例如「最缺蛋白质 → 仓库里放点肉或鱼」。
  - 熟练度只列最高三项。
- **调试页。** 完整营养说明（全部 `%+.2f` 行）、明日变化、工作资格阈值、原始坐标。

### 文案规则

所有玩家视图的文字照这几条写，英文同时写、口吻相同：

- 一句只说一件事；长句拆开，一个定语里最多一个「的」。
- 做法用动词开头：「通上暖气」「多放张绘图台」「整理来件」。
- 规则说明放进悬停提示，正文不讲道理。
- 标签和状态用两三个字：运转、受限、停工、缺料、完成、休养。
- 居民的话用口语短句，可以带语气，但数字和地点不能丢。
- 避开翻译腔：不用「进行」「对……进行」「当……时」「从……中」，少用被动句和「作为」。
- 「人手」和「效率」贯穿所有工作建筑：人手是按效率折算后的人数，个人只说效率。玩家视图里不出现「标准工人」「标准研究员」「人·天」。

## 验证

- **GameTest（不需要客户端）：**
  - 格式函数的边界：9.9 °C 对 10 °C 显示「太冷」；0.999 的能力显示「不足 1」；进度未完成时不显示 100%。

  - 用到的翻译键在 `zh_cn` 与 `en_us` 里都存在。
