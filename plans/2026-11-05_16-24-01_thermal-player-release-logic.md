## Verified Current State

- `PlayerThermalModel` 把辐射功率放入加权边界，再将除以换热系数后的平衡温度写入 `feelingTemperatureC`；`PlayerThermalInjury` 用其判断 ±100/150/200/250°C 的直接伤害。
- 衣物保温系数缩小空气导纳，直接辐射功率只受 radiant proof 影响，没有通过衣物隔热；已核对空气12°C、20W/m²时单羊毛夹克可将伤害输入推至约121°C。
- `addUniformBodyEnergyJ` 对最终温度无条件双向 clamp，已有温度超出食物上限时，热食可能反而降温；零输入也可能改变身体。
- 衣物属性 `MULTIPLY_BASE` 使用直接乘法，导致正向保温加成变成削弱；已与原版属性实例逐操作对照。
- 负重首次生效先解引用可能不存在的 `HEAVY_LOAD`；体温效果只在两个冷热效果均不存在时添加，不能即时降级/切换/恢复。
- 当前已登记的装备使用真实秒数消费资源、身体使用生理秒数积分；需在统一修改后验证间隔、耗尽和冻结。暖石交换/环境等效温度等只作积分的中间量不因名称删除。
- 工作区含其他会话修改与运行中的客户端；共享编译输出曾发生残缺。采用当前源码的独立构建输出和测试世界，不覆盖运行中的安装包。现有矿床 GameTest 编译错误属于其他范围，若仍存在则仅在临时编译配置中排除它们，明确记录。

## Implementation

1. 完成玩家、热物品、食物及玩法输入的调用/单位审查，区分已证实缺陷、设计政策和未完成的平衡校准。旧人物体温清零不改。
2. 辐射作为独立瓦数参与身体积分，并经过衣物传热与辐射防护。被动边界只由真实空气/接触介质组成，须位于这些介质温度范围内；不再把辐射除以小导纳后的值交给伤害。
3. 将部位伤害输入明确为接触环境温度和衣物传递比例。原严重冷热环境伤害保留，以真实暴露判定；辐射先进入身体热量，身体异常按实际部位体温处理。直接伤害的平均作用随实际游戏秒数变化，不随配置更新频率任意放大。
4. 检查积分、加热背心读取的被动净功率与辐射归属，保证没有双计或漏计。复用现有上下文，只有固定五部位的原始值，不增加任务/事件/缓存框架。
5. 食物仅沿其能量方向推进，达到该方向上限后不再推进；不能把已超界的部位瞬间拉回，零热量无身体副作用。负重正确添加/更新/移除。
6. 自有高低温效果按真实躯干温度及时选择、降级、切换和清除；不删除外部来源的原版药水效果。保留原有部位阈值与玩法基本规则。
7. 删除被替换的错误入口、含义混乱的内部 API 和无用包装；更新实际使用的诊断输出。数学求解中间量不作为人体或皮肤实测值。
8. 用少量专用 Forge 测试覆盖报错条件、相反方向/零输入、严重暴露、装备资源和效果更新；再选现有温泉/蓄热与真实篝火接线的重点验证。只在新变更、失败或具体未解问题时追加检查。
9. 更新当前玩家文档和本轮调查结果，记录验证产物及范围。没有测量的百人联网、完整旧版平衡或现场伤害来源不宣称通过。

## Closure Review

- 空气°C、接触边界°C、辐射W/m²、部位功率W、能量J与身体温差各有单一用途。
- 辐射/装备只计算一次，衣物不会通过小分母放大直接伤害；隔热同时限制外界热量传入。
- 身体/装备/效果使用同一更新结果，冻结与管理模式不消费加热资源。

- 旧人物热状态按用户要求清零；新格式保存读取不变。
- 运行时、多核和粗档协议不作本批无依据重写。
